## 끊겨도 이어서 올리기 — 큰 파일 올리기를 믿을 수 있게

큰 파일을 올리다 **연결이 끊기거나 다른 화면으로 가도 작업을 잃지 않도록** 올리기를 다시 짰습니다. 다른 탭으로
가도 진행률과 멈추기가 남고, 연결이 끊겨도 받은 데부터 이어 올리며, 이름이 겹치거나 용량이 넘칠 파일은 **올리기
전에** 알려 줍니다.

> **서버도 1.10.0 으로 올려 주세요.** 큰 파일 마무리가 빨라지고(아래 「서버」), 올리기 전 용량 검사가 서버 한도를
> 압니다. 옛 서버에서도 앱은 그대로 동작합니다(「호환」).

### 받을 것

| 파일 | 누구에게 |
| --- | --- |
| `listup-1.10.0-windows-setup.exe` | PC 앱. 이전 버전 위에 덮어 설치됩니다 — 서버 목록·설정·서버 데이터는 그대로 |
| `listup-1.10.0-android.apk` | 안드로이드 앱. **1.5.0 이상 위에 덮어 설치됩니다** (1.3.0 이면 [1.5.0 안내](https://github.com/yh-yeop/ListUp/releases/tag/v1.5.0)대로 한 번 지우고 설치) |
| `listup-1.10.0.zip` | 명령줄로 서버를 여는 사람. 압축을 풀고 `npm install` → `npm run serve -- --tunnel` |
| `latest.yml`, `….blockmap` | PC 앱 자동 업데이트가 읽는 파일입니다. 받을 필요 없습니다 |

1.7.0 이상 앱은 이 버전을 **알아서 받아 설치**합니다(PC 앱은 다시 시작할 때, 안드로이드는 알림에서 받아서 설치).
PC 앱은 코드 서명을 하지 않아 Windows 가 "PC 보호" 경고를 띄웁니다 — **추가 정보 → 실행**.

### 새로 된 것

- **화면을 옮겨도 올리기가 보입니다.** 올리는 중에 변경 이력·멤버 탭으로 가거나 다른 저장소를 열어도 화면 아래에
  진행 카드와 **멈추기**가 남습니다. 전에는 화면을 옮기면 진행률이 사라진 채 올리기만 계속됐고, 돌아와서 같은 파일을
  또 올릴 수 있었습니다. 이제 같은 저장소에 올리는 중이면 「파일 올리기」가 꺼지고, 끝나면 목록이 저절로 새로 보입니다.
- **끊겨도 이어서 올립니다.**
  - 연결이 끊기면 **5분** 동안 다시 붙어 이어 보냅니다(전에는 약 30초).
  - 그래도 끊겨 있으면 받은 데까지 **기억해 둡니다.** 20시간 안에 같은 파일(같은 위치·크기·고친 시각)을 다시 올리면
    처음부터가 아니라 **거기서 이어 갑니다** — 앱을 새로 고치거나 다시 켜도 됩니다.
  - 고친 시각을 모르는 파일은 처음부터 올립니다. 안드로이드에서 「파일 올리기」로 고른 파일이 여기에 듭니다(「폴더 올리기」는 이어 갑니다).
  - 끊긴 채로 끝나면 "연결이 끊겼습니다 — N/M개 올림" 으로 알리고, 다 올린 파일은 반영합니다.
- **올리기 전에 미리 알려 줍니다.** 이미 있는 파일과 이름이 같은 폴더(또는 그 반대), 저장소 파일 수(5,000개)·용량
  한도를 넘길 파일은 **한 바이트도 보내기 전에** "이름이 겹쳐 올릴 수 없습니다" 같은 안내로 막습니다. 전에는 다
  올린 뒤에야 실패하고 아무것도 반영되지 않았습니다. 고른 폴더가 5,000개를 넘으면 앞의 5,000개만 올린다고 확인창에 적습니다.
- **마무리 중에는 멈추기를 숨깁니다.** 다 보낸 뒤 서버가 마무리하거나 저장소에 반영하는 동안은 「서버에서 마무리하는
  중」·「반영하는 중」으로 보입니다 — 이때 멈춰도 소용이 없어 버튼을 감춥니다.
- **나가면 끊습니다.** 변경 제안을 쓰다 파일을 담는 중에 나가면(버리기 확인 뒤) 담던 업로드를 끊습니다. 서버를 바꾸거나
  로그아웃하면 진행 중이던 올리기를 멈추고, 이미 올린 파일을 다른 서버에 반영하지 않습니다.

### 서버

- **큰 파일 마무리가 빨라졌습니다.** 조각을 받을 때마다 해시를 이어 계산해, 다 받은 뒤 수 GB 파일을 처음부터 다시
  읽지 않습니다(끊긴 조각을 다시 받아도 이어 계산이 유지됩니다. 서버를 다시 켜면 그 파일만 예전처럼 다시 읽습니다).
- 마무리 응답을 놓친 앱이 10분 안에 다시 요청하면 같은 결과를 줍니다 — 다 보낸 파일을 처음부터 다시 올리지 않게.
- `/api/health` 가 저장소 용량 한도(`maxRepoBytes`)를 알려 줍니다 — 앱이 올리기 전 검사에 씁니다.

### 아직 안 된 것

- **안드로이드에서 받기**는 아직 진행률이 없고, 끊기면 처음부터 다시 받습니다. **PC 앱 받기**도 진행 표시가 없습니다.
  다음 버전에서 고칩니다.

### 호환

- **앱과 서버는 서로 따로 올려도 됩니다.** API 호환 버전(`apiVersion`)은 1 그대로이고, 기능 수준(`apiLevel`)이 **6** 이
  됐습니다. 1.10 앱이 옛 서버에 붙으면 이어 올리기·화면 이동·이름 충돌·파일 수 검사는 그대로 되고, **용량 검사만**
  건너뜁니다(옛 서버는 한도를 알려 주지 않습니다). 큰 파일 마무리 속도와 마무리 재요청은 서버를 올려야 적용됩니다.
- **1.9 이하 앱**은 1.10 서버에 그대로 붙습니다.
- **DB 구조:** 바뀌지 않았습니다.
