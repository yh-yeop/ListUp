## AI 에게 맡기기·초대 흐름·더 큰 저장소

Claude 같은 AI 가 저장소를 읽고 **변경 제안**을 올리게 하는 **MCP 서버**가 생겼고, 초대 링크로 들어온 사람이
**참여 뒤에 갈 곳을 잃던 화면**을 고쳤습니다. 저장소 하나에 담을 수 있는 기본 용량은 **10GB** 로 늘었습니다.
그 밖에 저장소 로직과 화면 흐름을 훑어 **34곳**을 다듬었습니다.

> 앱만 올려도 됩니다. 서버를 올리면 기본 저장소 용량이 10GB 가 되고 휴지통·목록이 빨라집니다(아래 「호환」).

### 받을 것

| 파일 | 누구에게 |
| --- | --- |
| `listup-1.9.0-windows-setup.exe` | PC 앱. 이전 버전 위에 덮어 설치됩니다 — 서버 목록·설정·서버 데이터는 그대로 |
| `listup-1.9.0-android.apk` | 안드로이드 앱. **1.5.0 이상 위에 덮어 설치됩니다** (1.3.0 이면 [1.5.0 안내](https://github.com/yh-yeop/ListUp/releases/tag/v1.5.0)대로 한 번 지우고 설치) |
| `listup-1.9.0.zip` | 명령줄로 서버를 여는 사람. 압축을 풀고 `npm install` → `npm run serve -- --tunnel` |
| `latest.yml`, `….blockmap` | PC 앱 자동 업데이트가 읽는 파일입니다. 받을 필요 없습니다 |

1.7.0 이상 앱은 이 버전을 **알아서 받아 설치**합니다(PC 앱은 다시 시작할 때, 안드로이드는 알림에서 받아서 설치).
PC 앱은 코드 서명을 하지 않아 Windows 가 "PC 보호" 경고를 띄웁니다 — **추가 정보 → 실행**.

### 새로 된 것

- **AI 에게 맡기기 — MCP 서버.** Claude 같은 MCP 클라이언트에 붙이면 AI 가 저장소 목록·파일·변경 이력·제안을 읽고,
  **변경 제안**과 **의견**을 올립니다. 파일을 이 PC 에 내려받을 수도 있습니다(절대 경로만, 이미 있는 파일은 덮어쓰라고
  할 때만).
  - **AI 전용 계정을 만들어 열람자로 초대하세요.** 열람자는 저장소를 직접 바꾸지 못하므로, AI 가 낸 변경은 편집자가
    검토하고 반영하기 전까지 들어가지 않습니다. 할 수 없는 일은 서버가 그 계정의 역할로 막습니다.
  - 설치와 Claude Code·Claude 데스크톱 설정은 README 의 **7. AI 에게 맡기기** 에 있습니다. 지금은 리포를 받아 `npm ci`
    한 뒤 `node <리포>/mcp/bin/listup-mcp.mjs` 로 등록합니다(위 배포 묶음에는 들어 있지 않습니다).
  - 1차는 읽기·제안·의견뿐입니다. 직접 편집·병합·멤버 관리 도구는 다음에 더합니다.
- **초대 링크로 들어온 뒤 갈 곳이 생겼습니다.**
  - 링크로 들어와 가입·로그인하고 참여하면 저장소 화면에서 **「내 저장소」 목록으로 돌아갈 길이 없었습니다**(안드로이드
    뒤로가기는 앱이 꺼졌습니다). 이제 참여한 저장소 밑에 목록이 깔립니다.
  - **회수·만료·소진된 초대**는 로그인 전에 "이 초대는 쓸 수 없습니다" 로 알립니다. 전에는 가입까지 한 뒤에야 오류
    화면에 갇혔습니다. 참여 화면에서 막히면 **내 저장소로** 버튼으로 나옵니다.
  - 초대 링크를 연 뒤 로그인 화면에서 **다른 서버로 바꿔 로그인하면** 엉뚱한 서버에 그 초대를 찾던 것을 고쳤습니다.
  - 목록에 없는 서버의 초대에서 "목록에 더할까요?" 를 취소했거나 연결이 안 됐으면 **그 서버로 들어가기** 로 다시 할
    수 있습니다.
- **저장소 기본 용량 10GB.** 저장소 하나의 총량 한도 기본값이 4GB 에서 10GB 가 됐습니다(서버를 올려야 적용).

### 다듬은 것

- **빨라진 것(서버).** 휴지통이 다른 저장소의 삭제 이력까지 훑던 것을 고쳐, 저장소가 많고 이력이 길 때 수백 ms 걸리던
  것이 수십 ms 가 됐습니다. 파일이 많은 폴더 목록(특히 **내 폴더와 비교**의 전체 목록)의 정렬이 수십 배 빨라졌고,
  과거 시점의 파일 하나를 받을 때 저장소 전체 목록을 다시 만들지 않습니다.
- **변경 제안.**
  - 「제안 올리기」가 흐려져 있으면 **왜 못 올리는지**(제목이 비었다, 담은 파일이 없다, 담는 중이다) 버튼 위에 적습니다.
  - 파일을 담는 중에는 올리기·나가기를 막아 담던 파일이 빠지지 않습니다. 여러 파일이 실패하면 몇 개가 왜 실패했는지 보입니다.
  - 반영이 충돌로 실패하면 화면을 새로 받아 "지금은 반영할 수 없습니다" 를 보이고, 편집자와 작성자에게 각자 할 일을 안내합니다.
  - 가득 찬 저장소(파일 5,000개)에서도 "하나 추가 + 하나 삭제" 제안을 만들 수 있습니다(반영은 원래 됐습니다).
- **파일.** 받는 중에 같은 행을 다시 눌러 받던 파일이 지워지던 것, 폴더를 옮긴 직후 이전 폴더 기준으로 덮어쓰기 확인을
  건너뛰던 것을 고쳤습니다. 이름 바꾸기 칸에 "앞의 폴더 부분을 지우면 맨 위로 옮겨집니다" 를 적었고, 휴지통에서 되돌린 뒤
  변경 이력이 바로 새로 보입니다. 큰 파일을 다 보낸 뒤 서버가 마무리하는 동안 "응답이 없습니다" 로 실패하던 것을 고쳤습니다.
- **멤버·계정.** 멤버 작업 중에는 다른 멤버 버튼을 막아 소유자 지정을 두 번 누르는 일이 없습니다. 소유자에게 "나가려면 먼저
  다른 멤버를 소유자로 지정하세요" 를 적었습니다. 로그아웃이 서버를 기다리는 동안 버튼에 표시가 나옵니다. 초대 목록의
  「사용 불가」에 이유(횟수 모두 사용·발급자 권한 없음)가 붙습니다.
- **서버를 여는 사람.** 오래 방치된 제안용 파일을 다시 올리면 정리 작업(GC) 유예가 새로 시작돼, 올리자마자 지워져 제안이
  "먼저 파일을 업로드해 주세요" 로 실패하던 일이 없습니다.

### 호환

- **앱과 서버는 서로 따로 올려도 됩니다.** API 호환 버전(`apiVersion`)과 기능 수준(`apiLevel` 5)은 그대로입니다.
- **「서버를 올리면」** 저장소 기본 용량 10GB, 휴지통·목록 속도, GC 유예 갱신이 적용됩니다. `LISTUP_MAX_REPO_MB` 를 직접
  정한 서버는 그 값 그대로입니다.
- **「바뀐 것」** 변경 이력·파일 버전 목록의 커서를 `before`·`beforeId` 중 하나만 보내면 이제 **400** 입니다(전에는 조용히
  첫 페이지를 줘서 같은 페이지를 되풀이할 수 있었습니다). 앱은 늘 둘을 함께 보내므로 영향이 없습니다. 범위 요청 `bytes=5-2`
  처럼 시작이 끝보다 크면 416 대신 전체(200)를 줍니다.
- **DB 구조:** 바뀌지 않았습니다.
