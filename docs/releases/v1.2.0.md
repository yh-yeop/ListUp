## 파일 공유 다듬기 — 큰 파일, 폴더, 링크로 나누기

ListUp 의 본업인 **파일을 주고받고 남에게 나누는 것**을 다듬었습니다.

### 받을 것

| 파일 | 누구에게 |
| --- | --- |
| `listup-1.2.0-android.apk` | 안드로이드 폰에 설치하는 앱. 1.1.0 위에 덮어 설치됩니다 |
| `listup-1.2.0.zip` | 서버를 여는 사람. 압축을 풀고 `npm install` → `npm run serve -- --tunnel` |

### 새로 된 것

- **큰 파일** — 한 파일 2GB 까지(기본값, 이전 100MB). 8MB 조각으로 나눠 올려 **진행률**이 보이고,
  연결이 끊겨도 받은 데까지에서 **이어서** 올립니다. 터널의 요청 크기 한도에도 걸리지 않습니다.
- **폴더 올리기** — 웹과 안드로이드에서 폴더를 골라 하위 폴더 구조 그대로 올리고, 커밋 하나로 남깁니다.
- **폴더 zip 받기** — 폴더 옆 버튼으로 폴더(또는 저장소 전체)를 zip 하나로 받습니다.
- **내려받기** — 브라우저·폰의 다운로드 기능으로 디스크에 바로 받습니다(메모리에 올리지 않음). 이어받기가 됩니다.
- **초대 링크** — 초대 화면의 "링크 복사·공유". 받은 사람은 링크 하나로 가입·로그인 → 미리보기 → 참여까지
  갑니다. 웹에서 "설치한 앱에서 열기"를 누르면 앱이 그 서버를 목록에 더하고 들어갑니다.
- **비밀번호 재설정** — 서버를 돌리는 사람이 `npm run reset-password -- <이메일>` 로 코드(30분·한 번)를 주면,
  로그인 화면의 "비밀번호를 잊었나요?" 에서 새 비밀번호를 정합니다.
- **앱 아이콘**.
- **이력 저장 방식** — 커밋마다 바뀐 파일만 기록합니다. 파일이 많은 저장소에서 DB 가 훨씬 작고 커밋이 빠릅니다.

### 호환

- **1.2.0 앱은 1.2.0 이상 서버에만 들어갑니다** (서버 목록에 "서버가 오래됨"). 새 업로드·내려받기 방식을 쓰기 때문입니다.
- 1.1.0 앱은 1.2.0 서버에 그대로 붙습니다.

### 서버를 1.1.0 에서 올리는 사람

데이터(`server/data`)는 그대로 쓰지만, **처음 켤 때 DB 구조를 옮깁니다**(이력 저장 방식 변경, 되돌릴 수 없음).
켜기 전에 백업하세요.

```bash
npm run backup -- ./backups
```

파일이 많은 DB 는 옮긴 뒤 한 번 압축(VACUUM)하느라 첫 기동이 조금 걸립니다. 음악 539곡·551커밋 DB 로
옮기기 전후 모든 시점의 파일 목록이 같은 것을 확인했습니다.
