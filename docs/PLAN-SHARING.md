## A. 테스트를 저장소로

- `e2e/` 에 스펙(서버 목록 35 · 클라이언트 모드 21 · 버전 11 · 로그인 저장 28 · 업데이트 12)과 실행기.
- 실행기가 **빈 포트를 골라** 서버 A·B(임시 DB), 클라이언트 모드 웹용 정적 서버, 버전 가짜 서버를 띄우고
  웹을 두 모드로 빌드한 뒤 스펙을 돌린다. 스펙은 주소를 하드코딩하지 않고 받는다(지금 쓰고 있는
  음악 서버 포트와 부딪히지 않게).
- 브라우저: Windows 는 설치된 Edge, CI 는 `playwright-core` 가 받는 Chromium.
- CI(`.github/workflows/ci.yml`): typecheck → 서버 테스트 → e2e.

## B. 저장 구조 — 바뀐 것만 기록

**지금.** `snapshot_entries` 가 스냅샷마다 저장소의 **모든** 파일 행을 가진다. 파일 F 개 저장소에
커밋 C 번이면 F×C 행. 폴더를 파일마다 올리면 C≈F 라 F² 에 가깝다.

**바꿀 모양.**

```
repo_files        (repo_id, path) → blob_hash, size, mime_type, updated_at   -- 지금 상태(head)
snapshot_changes  (snapshot_id, path) → new(hash,size,mime,updated) | null, old(...) | null
snapshots         + file_count, total_size                                    -- 이력 목록용
```

- **head 읽기**(목록·내려받기·업로드·제안)는 `repo_files` 한 번.
- **과거 시점 읽기**는 head 에서 시작해, 그 시점 이후의 변경을 **최근 것부터 거꾸로 되돌린다**
  (old 값으로). 과거 보기는 드물고, 되돌리는 양은 그 시점 이후의 변경 수만큼이다.
- **커밋**은 바뀐 경로만 `snapshot_changes` 에 쓰고 `repo_files` 를 고친다. 파일 수와 무관.
- **여러 파일 커밋**: `POST /repos/:id/files/commit` `{changes:[{path, blobHash|null}]}` → 스냅샷 하나.
  폴더 올리기·동기화 스크립트가 쓴다.
- **blob 참조**(GC·제안에 담을 수 있는지)는 `repo_files` ∪ `snapshot_changes` 의 new·old.

**이전(마이그레이션).** 새 표를 만들고, 저장소마다 스냅샷을 오래된 것부터 이웃끼리 비교해 변경분을
채우고, head 로 `repo_files` 를 채운 뒤 `snapshot_entries` 를 지운다. 표를 새로 만들고 지우기만 해서
P3 의 "FK 켠 채 표 재작성" 문제에 걸리지 않는다.

**검증 — 실제 음악 DB 사본으로.** `npm run backup` 으로 뜬 사본에 이전을 돌리고, **모든 스냅샷에 대해
되돌려 만든 목록이 이전 전 `snapshot_entries` 와 똑같은지** 전부 대조한다. 행 수·DB 크기 전후도 잰다.
실서버 데이터는 사용자가 확인한 뒤에 옮긴다(서버를 켜면 자동 이전되므로, 켜기 전에 백업).

## C. 전송

**나눠 올리기(재개 가능).** 한 요청 본문이 Cloudflare 한도(100MB)를 넘지 않게 8MB 씩.

```
POST /repos/:id/uploads          {size, name}        → {uploadId, chunkSize, received}
PUT  /uploads/:uploadId?offset=N  (바이트)            → {received}   offset 이 어긋나면 409 {received}
GET  /uploads/:uploadId                              → {received, size}   끊긴 뒤 이어서
POST /uploads/:uploadId/complete                     → {blob:{hash,size,mimeType,name}}
```

- 조각은 임시 파일에 이어 붙이고, 완료 때 해시를 구해 콘텐츠 주소로 옮긴다. 세션은 DB 에 두어 서버를
  다시 켜도 이어진다. 오래 멈춘 세션은 GC 가 지운다.
- 완료된 blob 은 B 의 여러 파일 커밋이나 기존 변경 제안(`blobHash`)에 쓴다. 한도(파일 하나·저장소
  총량·하루 스테이징)는 세션을 만들 때 크기로 먼저 보고 완료·커밋 때 다시 본다.
- 기존 multipart 업로드는 그대로 둔다(다른 클라이언트·스크립트 호환).

**진행률.** 앱의 올리기는 조각을 `XMLHttpRequest` 로 보내 조각 안 진행률까지 합산해 보여 준다.
네이티브는 `FileHandle.readBytes` 로 8MB 씩 읽는다. 폴더·여러 파일은 "3/10 · 45%".

**이어받기와 브라우저 다운로드.**
- 서버 `sendBlob` 이 `Range`(단일 구간)·`If-Range`·`Accept-Ranges` 를 지원 → 206 / 416.
- **짧게 사는 다운로드 링크**: `POST .../download-link` 가 그 파일 하나에 묶이고 몇 분 뒤 만료되는 서명
  URL 을 준다. 웹은 이 URL 을 브라우저에 넘겨 **브라우저 자체 다운로드**(디스크로 바로 저장, 진행률,
  이어받기)를 쓴다 — 지금은 파일 전체를 메모리(Blob)로 받는다.
- 네이티브는 진행률이 나오는 다운로드 작업으로 받아 공유 시트로.

**폴더.**
- 올리기: 웹은 폴더 선택(`webkitdirectory`, 경로 유지), 안드로이드는 폴더 선택기(`Directory.pickDirectoryAsync`)
  를 훑어 상대 경로 유지 → 조각 업로드 → **커밋 하나**.
- 받기: `GET /repos/:id/archive?path=&snapshot=` 가 zip 을 흘려보낸다(압축 없이 담기, ZIP64 — 저장소
  한도 4GB 근처라). `yazl` 사용. 다운로드 링크로 브라우저가 받는다.

## D. 나누기

**초대 링크.** `https://<서버주소>/join?code=ABCDE12345` 하나.
- 어디서나 눌린다(메신저가 `listup://` 는 링크로 안 만드는 경우가 많다).
- 서버가 주는 웹의 참여 화면이 로그인·가입 → 미리보기 → 참여를 이어 준다(코드를 가입 뒤까지 들고 감).
- 그 화면에 **"앱에서 열기"** (`listup://join?server=<주소>&code=<코드>`). 앱은 서버가 목록에 없으면
  연결 확인 뒤 추가하고, 로그인·가입을 거쳐 참여까지 간다.
- 앱의 초대 화면에 "링크 복사·공유". 지금 서버 주소가 공유기 안 주소(192.168… 등)면 "같은 공유기에서만
  열립니다" 경고.

**비밀번호 재설정 코드.** 저장소 소유자는 서버 운영자가 아니므로(남의 계정을 풀 권한을 주면 안 된다)
**서버를 돌리는 사람이** 발급한다.
- `npm run reset-password -- <이메일>` → 한 번 쓰는 코드(30분). DB 에는 해시만(`password_resets`, 추가 마이그레이션).
- 앱 로그인 화면 "비밀번호를 잊었나요" → 이메일·코드·새 비밀번호 → `POST /auth/reset` → 비밀번호 변경 +
  토큰 세대 올림(다른 기기 로그아웃). 로그인 실패 제한과 같은 방식으로 시도 횟수를 센다.

**고정 주소**는 사용자의 Tailscale·Cloudflare 계정이 있어야 해서 코드 일이 아니다 — 준비 상태만 점검해 알린다.
